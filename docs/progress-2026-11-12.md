# WiSec Assistant: Progress Update

Advanced Database Systems, Final Project (Option 2) · November 12, 2026 · Sarra Rashd

## Summary

The search back end is complete: the system indexes 11 wireless security documents, searches them by meaning or by keyword, and exposes that search through a working MCP server with four tested tools. The chatbot, the evaluation, and the final report and slides remain before submission on December 3, 2026.

## Completed Work

Seven components are built, tested and committed to GitHub.

| Component | Result |
| --- | --- |
| Document collection | 11 NIST and NSA documents, 382 pages, covering Wi-Fi, Bluetooth, LTE and 5G |
| Relational metadata database | SQLite with `documents`, `chunks` and `query_log` tables, keys and constraints |
| Processing pipeline | PDFs cleaned and split into 2,286 chunks of 500 characters and 690 of 1,500 |

| MCP server | Four tools: `search_documents`, `get_document`, `list_documents`, `provide_feedback`; tested with 7 sample requests, including an error case |

## Preliminary Findings

In two test questions, semantic search held up when the question's wording differed from the documents; keyword search did not. These are early observations, not final results: they will be confirmed with a test set of 12–15 questions, each labeled with the document that contains its answer. A result will count as relevant when it comes from that document and addresses the question.

| Question | Semantic search | Keyword search |
| --- | --- | --- |
| How can I protect my phone when using public Wi-Fi? (same words as the document) | 3 of 5 useful, 0.75 s | 2 of 5 useful plus 1 partial, 0.00 s |
| Is it safe to pair my wireless headphones? (different words) | 2 strong and 2 partial, all about Bluetooth | 0 of 5 useful; 2 from the withdrawn SP 800-97 |

Four limitations will go into the final report:

- Reference lists at the end of documents appear in results for both methods.
- The withdrawn SP 800-97 produces about 47% of all chunks, so it can crowd out newer guidance.
- Page numbers are PDF page positions, which can differ from the numbers printed in the document.
- The embedding model reads about 1,000 characters, so the end of each 1,500-character chunk is not used for search.
